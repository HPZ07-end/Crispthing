# 自主跟随搬运小车调试命令表

**项目**：果园自主跟随搬运小车  
**文档版本**：v0.1  
**适用阶段**：ESP32 板子到货前 / 到货后早期调试  
**适用程序**：`follow_car_main_v0.ino`  

---

## 1. 文档目的

本文件用于说明 ESP32 程序在调试阶段使用的串口命令。  
这些命令用于在真实手柄、ToF 传感器、电机、手机/OpenBot 通信尚未接入时，手动模拟系统输入，提前测试状态机逻辑是否正确。

需要注意：

> 本文档中的字母命令是调试命令，不代表最终手柄真的会发送这些字母。

正式系统中，真实输入会来自：

- 手柄摇杆与按钮；
- ToF 测距模块；
- 手机/OpenBot 视觉识别结果；
- 急停按钮；
- 电机驱动反馈，后续可选。

但不管输入来自哪里，ESP32 内部最终都会转换成统一控制命令，再交给状态机处理。

---

## 2. 串口调试环境设置

调试时使用 Arduino IDE 的串口监视器。

| 项目 | 设置 |
|---|---|
| 波特率 | `115200` |
| 行尾 | `Newline` 或 `Both NL & CR` |
| 开发板 | `ESP32S3 Dev Module` |
| 程序 | `follow_car_main_v0.ino` |
| 调试方式 | 在串口输入框中输入单个字母命令并回车 |

如果输入命令后没有反应，优先检查：

1. 串口波特率是否为 `115200`；
2. 行尾是否选择了 `Newline` 或 `Both NL & CR`；
3. 是否选对 COM 口；
4. 程序是否已经上传成功；
5. 串口监视器是否重新打开。

## 3. 调试命令总表

| 串口输入 | 英文含义 | 模拟对象 | 对应含义 |
|---|---|---|---|
| `T` | Target visible | 手机/OpenBot | 假装识别到目标人 |
| `N` | Target lost | 手机/OpenBot | 假装目标人丢失 |
| `A` | Auto mode | AUTO 按钮 | 请求进入自动跟随模式 |
| `M` | Manual mode | MANUAL 按钮 | 请求进入手动模式 |
| `S` | Stop | STOP 按钮 | 普通停车；调试时也用于急停复位 |
| `E` | Emergency | 急停按钮 | 进入急停状态 |
| `F` | Forward | 摇杆前推 | 手动前进 |
| `B` | Backward | 摇杆后拉 | 手动后退 |
| `L` | Left | 摇杆左推 | 手动左转 |
| `R` | Right | 摇杆右推 | 手动右转 |
| `O` | Obstacle front | ToF | 假装前方有障碍，左侧可绕 |
| `C` | Clear obstacle | ToF | 清除障碍物模拟数据 |
| `X` | All blocked, rear safe | ToF | 假装前/左/右都堵住，但后方安全 |

## 4. 各命令详细说明

### 4.1 `T`：模拟识别到目标人

输入：

```text
T
```

作用：模拟手机/OpenBot 已经识别到目标人。程序中会设置：

```cpp
targetVisible = true;
targetDistance = 1.6;
targetX = 0.0;
```

含义：

- 目标人可见；
- 目标距离约 1.6 m；
- 目标位于画面中间。

典型用途：进入自动模式前，先输入 `T`，否则程序会认为没有目标人，不允许进入自动跟随。

---

### 4.2 `N`：模拟目标丢失

输入：

```text
N
```

作用：模拟手机/OpenBot 暂时看不到目标人。程序中会设置：

```cpp
targetVisible = false;
targetDistance = 999.0;
```

典型状态变化：

```text
AUTO → REACQUIRE
```

含义：自动跟随中目标丢失，小车应停止并进入目标重捕获状态。

---

### 4.3 `A`：请求自动跟随

输入：

```text
A
```

作用：模拟按下 AUTO 自动模式按钮。

进入 AUTO 的条件：

```text
targetVisible = true
```

也就是说，一般需要先输入：

```text
T
A
```

预期状态：

```text
IDLE → AUTO
```

如果没有先输入 `T`，系统会保持 `IDLE`，并提示目标不可见。

---

### 4.4 `M`：请求手动模式

输入：

```text
M
```

作用：模拟按下 MANUAL 手动模式按钮。

预期状态：

```text
任意非急停状态 → MANUAL
```

说明：手动模式优先级高于自动跟随。进入手动模式后，自动跟随指令暂停，由人工输入控制。

---

### 4.5 `S`：普通停车 / 调试复位

输入：

```text
S
```

作用：模拟按下 STOP 普通停车按钮。

预期状态：

```text
任意非急停状态 → IDLE
```

在当前调试程序中，`S` 也临时用于从急停状态恢复到 `IDLE`。

注意：真实系统中，急停恢复不建议只靠软件命令，最好使用实体复位按钮或人工确认流程。

---

### 4.6 `E`：急停

输入：

```text
E
```

作用：模拟急停按钮被按下。

预期状态：

```text
任意状态 → EMERGENCY
```

急停状态下，应立即停止所有运动输出。真实小车中，急停应优先切断电机驱动使能或电机动力电源。

调试程序中可输入：

```text
S
```

从 `EMERGENCY` 回到 `IDLE`。

---

### 4.7 `F` / `B` / `L` / `R`：模拟手柄摇杆方向

| 命令 | 模拟操作 | 预期状态 | 动作 |
|---|---|---|---|
| `F` | 摇杆前推 | `MANUAL` | 前进 |
| `B` | 摇杆后拉 | `MANUAL` | 后退 |
| `L` | 摇杆左推 | `MANUAL` | 左转 |
| `R` | 摇杆右推 | `MANUAL` | 右转 |

说明：

这些命令用于模拟手柄方向输入。真实手柄接入后，摇杆的 X/Y 轴模拟电压会被 ESP32 读取，并转换成同样的内部命令。

---

### 4.8 `O`：模拟前方障碍，左侧可绕

输入：

```text
O
```

作用：模拟 ToF 检测到前方障碍，且左侧空间较大。程序中会设置：

```cpp
tofFront = 0.3;
tofLeft = 1.0;
tofRight = 0.4;
tofRear = 1.0;
```

含义：

- 正前方 0.3 m，有障碍；
- 左侧 1.0 m，可绕行；
- 右侧 0.4 m，不建议绕行；
- 后方 1.0 m，安全。

典型状态变化：

```text
AUTO → BYPASS
```

预期动作：

```text
ACTION: TURN LEFT
```

---

### 4.9 `C`：清除障碍模拟

输入：

```text
C
```

作用：清除前面通过 `O` 或 `X` 模拟的障碍物数据。

程序中会设置：

```cpp
tofLeft = 999.0;
tofFront = 999.0;
tofRight = 999.0;
tofRear = 999.0;
```

含义：四周均认为安全。

典型状态变化：

```text
BYPASS → REACQUIRE → AUTO
```

如果目标仍然可见，则系统会回到自动跟随。

---

### 4.10 `X`：模拟前/左/右都堵住，但后方安全

输入：

```text
X
```

作用：模拟前方、左侧、右侧都被堵住，但后方安全，可以倒车脱困。

程序中会设置：

```cpp
tofFront = 0.3;
tofLeft = 0.3;
tofRight = 0.3;
tofRear = 1.0;
```

典型状态变化：

```text
BYPASS → BACKUP → BYPASS
```

说明：当前 v0 程序中，`BACKUP` 状态切换速度较快，串口上可能只短暂出现。后续 v1/v2 中应加入倒车计时器，使倒车脱困过程更清晰。

## 5. 推荐测试流程

### 测试 1：启动状态测试

上传程序后打开串口监视器，观察是否周期性输出：

```text
STATE = IDLE
```

通过标准：

- 能持续输出状态信息；
- 初始状态为 `IDLE`；
- 没有自动进入其他状态。

---

### 测试 2：自动跟随进入测试

输入顺序：

```text
T
A
```

预期结果：

```text
STATE = AUTO
ACTION: FORWARD, speed = 60
```

通过标准：

- 输入 `T` 后，`targetVisible = YES`；
- 输入 `A` 后，状态从 `IDLE` 变为 `AUTO`；
- 程序输出前进动作。

---

### 测试 3：没有目标时不能进入自动模式

输入顺序：

```text
N
A
```

预期结果：

```text
AUTO requested, but target not visible. Stay IDLE.
STATE = IDLE
```

通过标准：

- 没有识别到目标人时，不允许进入自动跟随；
- 系统保持安全停车状态。

---

### 测试 4：前方障碍绕行测试

输入顺序：

```text
T
A
O
```

预期结果：

```text
STATE = BYPASS
ACTION: TURN LEFT, speed = 40
```

通过标准：

- 自动模式下遇到前方障碍，进入 `BYPASS`；
- 左侧空间足够时，选择左绕。

---

### 测试 5：清除障碍后恢复自动跟随

在测试 4 后继续输入：

```text
C
```

预期结果：

```text
STATE = REACQUIRE
STATE = AUTO
```

通过标准：

- 障碍清除后，系统进入目标重捕获；
- 若目标仍可见，恢复自动跟随。

---

### 测试 6：目标丢失测试

输入顺序：

```text
T
A
N
```

预期结果：

```text
STATE = REACQUIRE
```

通过标准：

- 自动跟随中目标丢失后，不继续盲目前进；
- 系统进入重捕获状态。

---

### 测试 7：手动接管测试

输入任意一个方向命令：

```text
F
```

或者：

```text
B
L
R
```

预期结果：

```text
STATE = MANUAL
ACTION: FORWARD / BACKWARD / TURN LEFT / TURN RIGHT
```

通过标准：

- 手动方向命令可以让系统进入 `MANUAL`；
- 手动模式优先于自动跟随。

---

### 测试 8：急停测试

输入：

```text
E
```

预期结果：

```text
STATE = EMERGENCY
ACTION: EMERGENCY STOP
```

再输入：

```text
S
```

预期结果：

```text
STATE = IDLE
```

通过标准：

- 任意状态下输入 `E` 都能进入急停；
- 急停后不会继续执行前进、绕障等动作；
- 当前调试版本中，`S` 可用于恢复到 `IDLE`。

## 7. 当前版本限制

当前 `follow_car_main_v0` 仍属于软件调试版，限制如下：

1. 不读取真实手柄；
2. 不读取真实 ToF；
3. 不控制真实电机；
4. 不接收真实手机/OpenBot 数据；
5. 电机动作目前只是串口打印；
6. `BACKUP` 倒车脱困状态尚未加入真实计时器。

后续版本规划：

| 版本 | 目标 |
|---|---|
| `v0` | 串口模拟状态机 |
| `v1` | 加入真实手柄输入 |
| `v2` | 加入 ToF 测距 |
| `v3` | 加入电机驱动控制 |
| `v4` | 系统集成测试 |

---

## 8. 核心原则

1. 急停优先级最高；
2. 手动接管优先于自动跟随；
3. 自动模式下，人靠近车时停车，不自动倒退；
4. 倒车只用于人工控制或绕障失败后的脱困；
5. 遇到前方障碍时优先停车、判断绕行空间，再决定绕行；
6. 调试命令只是模拟输入，真实系统需要接入传感器和手柄后再次验证。
