# 自主跟随搬运小车手柄接线与输入说明

**项目**：果园自主跟随搬运小车  
**文档版本**：v0.1  
**适用阶段**：手柄硬件到货前 / 接线前准备  
**控制板**：微雪 ESP32-S3-DEV-KIT-N16R8-M  

---

## 1. 文档目的

本文件用于说明物理手柄如何接入 ESP32，并解释手柄输入如何转换成小车的内部控制命令。

本项目手柄方案暂定为：

> 一个双轴摇杆 + 若干按钮。

手柄用于实现：

- 手动前进；
- 手动后退；
- 手动左转；
- 手动右转；
- 自动模式切换；
- 手动模式切换；
- 普通停车；
- 急停。

---

## 2. 手柄不是直接发送字母命令

调试程序中使用的 `F/B/L/R/A/M/S/E` 是串口调试命令。真实手柄并不会直接发送这些字母。

真实手柄的工作方式是：

```text
摇杆 X 轴 → 输出模拟电压 → ESP32 ADC 读取
摇杆 Y 轴 → 输出模拟电压 → ESP32 ADC 读取
按钮 → 输出高/低电平 → ESP32 GPIO 读取
```

ESP32 读取这些电压和电平之后，再在程序内部转换成统一命令：

| 真实手柄输入 | ESP32 内部命令 | 含义 |
|---|---|---|
| 摇杆前推 | `CMD_FORWARD` | 前进 |
| 摇杆后拉 | `CMD_BACKWARD` | 后退 |
| 摇杆左推 | `CMD_LEFT` | 左转 |
| 摇杆右推 | `CMD_RIGHT` | 右转 |
| AUTO 按钮按下 | `CMD_AUTO_MODE` | 请求自动跟随 |
| MANUAL 按钮按下 | `CMD_MANUAL_MODE` | 请求手动模式 |
| STOP 按钮按下 | `CMD_STOP` | 普通停车 |
| E-STOP 按钮按下 | `CMD_EMERGENCY` | 急停 |

所以，调试命令和真实手柄的关系是：

```text
串口字母命令：用于早期模拟输入
真实手柄输入：用于正式控制输入
二者最终都转换成同一套内部命令
```

## 3. 手柄硬件组成

推荐手柄至少包含以下部分：

| 部件 | 数量 | 作用 |
|---|---:|---|
| 双轴摇杆模块 | 1 | 控制前后左右运动 |
| AUTO 按钮 | 1 | 进入自动跟随模式 |
| MANUAL 按钮 | 1 | 进入手动模式 |
| STOP 按钮 | 1 | 普通停车 |
| E-STOP 急停按钮 | 1 | 紧急停止 |
| 外壳/固定板 | 1 | 固定摇杆和按钮 |
| 杜邦线/端子线 | 若干 | 连接 ESP32 |

可选部件：

| 部件 | 作用 |
|---|---|
| ENABLE 使能按钮 | 按住才允许手动运动，增加安全性 |
| 蜂鸣器 | 按键反馈、急停报警 |
| LED 指示灯 | 显示 AUTO/MANUAL/EMERGENCY 状态 |
| 摇杆自带 SW 按钮 | 可作为普通停车或使能按钮 |

## 4. 摇杆模块接线说明

常见双轴摇杆模块一般有 5 个引脚：

| 摇杆引脚 | 含义 | 接到 ESP32 |
|---|---|---|
| `VCC` | 电源正极 | `3V3` |
| `GND` | 地 | `GND` |
| `VRx` | 左右方向模拟输出 | ADC 输入引脚，待定 |
| `VRy` | 前后方向模拟输出 | ADC 输入引脚，待定 |
| `SW` | 摇杆按下按钮，可选 | 普通 GPIO，待定 |

重要注意事项：

> 摇杆 VCC 建议接 ESP32 的 `3V3`，不要接 `5V`。

原因：ESP32 的 GPIO 和 ADC 输入一般不能承受 5V。若摇杆 VCC 接 5V，则 `VRx/VRy` 可能输出 0–5V，容易损坏 ESP32。

推荐接法：

```text
摇杆 VCC  → ESP32 3V3
摇杆 GND  → ESP32 GND
摇杆 VRx  → ESP32 ADC 引脚
摇杆 VRy  → ESP32 ADC 引脚
摇杆 SW   → ESP32 GPIO，可选
```

---

## 5. 按钮接线说明

按钮推荐采用“低电平有效”接法。

接线方式：

```text
按钮一端 → ESP32 GPIO
按钮另一端 → GND
```

程序中使用：

```cpp
pinMode(PIN_BTN_AUTO, INPUT_PULLUP);
pinMode(PIN_BTN_MANUAL, INPUT_PULLUP);
pinMode(PIN_BTN_STOP, INPUT_PULLUP);
pinMode(PIN_BTN_ESTOP, INPUT_PULLUP);
```

此时按钮状态为：

| 按钮状态 | GPIO 读数 |
|---|---|
| 未按下 | `HIGH` |
| 按下 | `LOW` |

程序中对应逻辑：

```cpp
bool readButton(int pin) {
  return digitalRead(pin) == LOW;
}
```

这种接法的优点：

1. 不需要外接上拉电阻；
2. 接线简单；
3. 抗干扰能力比悬空输入更好；
4. 适合初版原型。

## 6. 初版引脚分配建议

当前程序中的占位引脚为：

```cpp
const int PIN_JOY_X = 1;
const int PIN_JOY_Y = 2;

const int PIN_BTN_AUTO   = 4;
const int PIN_BTN_MANUAL = 5;
const int PIN_BTN_STOP   = 6;
const int PIN_BTN_ESTOP  = 7;
```

对应表格：

| 功能 | 程序变量 | ESP32 引脚 | 说明 |
|---|---|---|---|
| 摇杆 X 轴 | `PIN_JOY_X` | GPIO1 | ADC 输入，左右方向 |
| 摇杆 Y 轴 | `PIN_JOY_Y` | GPIO2 | ADC 输入，前后方向 |
| AUTO 按钮 | `PIN_BTN_AUTO` | GPIO4 | 低电平有效 |
| MANUAL 按钮 | `PIN_BTN_MANUAL` | GPIO5 | 低电平有效 |
| STOP 按钮 | `PIN_BTN_STOP` | GPIO6 | 低电平有效 |
| E-STOP 按钮 | `PIN_BTN_ESTOP` | GPIO7 | 低电平有效 |

注意：

> 以上引脚是软件初版占位方案，正式接线前必须结合实际开发板丝印、扩展模块、ToF、电机驱动占用情况再确认。

建议暂时避免优先使用以下引脚：

| 引脚 | 原因 |
|---|---|
| GPIO0 | 常与 BOOT/下载模式有关 |
| GPIO19 / GPIO20 | ESP32-S3 常与 USB D-/D+ 有关 |
| GPIO43 / GPIO44 | 常与串口下载/调试有关 |
| GPIO45 / GPIO46 | 部分板上可能是特殊功能或启动相关引脚 |

最终引脚分配应统一写入：

```text
引脚分配表.md
```

## 7. 手柄输入的软件转换逻辑

### 7.1 摇杆模拟值

ESP32 使用 `analogRead()` 读取摇杆电压。

一般范围：

```text
最小值：约 0
中间值：约 2048
最大值：约 4095
```

程序中可以把它归一化成：

```text
-1.0 ~ 1.0
```

含义：

| 归一化值 | 含义 |
|---|---|
| 接近 0 | 摇杆在中间 |
| 接近 1 | 摇杆向正方向推到底 |
| 接近 -1 | 摇杆向负方向推到底 |

---

### 7.2 摇杆死区

摇杆在中间时不一定刚好等于 2048，可能会轻微抖动。因此需要设置死区。

建议初始死区：

```cpp
const float JOY_DEADZONE = 0.20;
```

含义：

```text
摇杆偏移小于 20% 时，认为没有动作
```

这样可以避免摇杆松手后，小车仍然缓慢移动。

---

### 7.3 方向判断

初版可以用“哪个轴偏移更大”来判断运动方向。

示意逻辑：

```cpp
if (fabs(y) >= fabs(x)) {
  if (y > JOY_DEADZONE) {
    return {CMD_FORWARD, 60};
  } else if (y < -JOY_DEADZONE) {
    return {CMD_BACKWARD, 40};
  }
} else {
  if (x > JOY_DEADZONE) {
    return {CMD_RIGHT, 45};
  } else if (x < -JOY_DEADZONE) {
    return {CMD_LEFT, 45};
  }
}
```

如果测试发现方向反了，例如：

```text
摇杆前推，小车却后退
```

则把 `CMD_FORWARD` 和 `CMD_BACKWARD` 对调。

如果发现：

```text
摇杆左推，小车却右转
```

则把 `CMD_LEFT` 和 `CMD_RIGHT` 对调。

## 8. 按钮功能定义

| 按钮 | 功能 | 优先级 |
|---|---|---:|
| E-STOP | 急停 | 最高 |
| STOP | 普通停车 | 高 |
| MANUAL | 手动接管 | 高于自动 |
| AUTO | 自动跟随 | 低于手动和安全保护 |

优先级原则：

```text
E-STOP > STOP > MANUAL > AUTO
```

更完整的系统优先级为：

```text
急停 > ToF安全约束 > 手动接管 > 绕障/脱困 > 自动跟随 > 待机
```

## 10. 急停设计建议

急停建议分成两层。

### 10.1 软件急停

软件急停接到 ESP32 GPIO，例如：

```text
E-STOP 按钮 → GPIO7
```

程序检测到按下后，进入：

```text
STATE_EMERGENCY
```

并停止输出电机控制信号。

### 10.2 硬件急停

真实小车上，仅靠软件急停不够安全。建议额外设置硬件急停，直接切断：

- 电机驱动 EN 使能；或
- 电机动力电源；或
- 电机驱动控制电源。

推荐原则：

> 软件急停用于程序状态控制，硬件急停用于保证电机真的失去动力。

急停按钮最好安装在车体明显、容易按到的位置。

## 11. 上电前检查清单

接线完成后，上电前必须检查：

```text
[ ] 摇杆 VCC 是否接 3.3V，而不是 5V
[ ] 摇杆 GND 是否接 ESP32 GND
[ ] VRx/VRy 是否接到 ADC 引脚
[ ] 按钮是否一端接 GPIO，一端接 GND
[ ] 是否没有让 GPIO 直接接到 5V
[ ] 是否没有短接 3.3V 和 GND
[ ] 急停按钮是否能正常按下和弹起
[ ] 杜邦线是否插牢
[ ] 电机电源是否暂时没有接入
```

第一次测试手柄时建议：

> 只接 ESP32 和手柄，不接电机驱动动力电源。

确认手柄输入读数正常后，再接电机驱动。

## 12. 手柄测试流程

### 12.1 第一步：测试按钮

目标：确认 AUTO、MANUAL、STOP、E-STOP 能被 ESP32 正确读取。

测试方法：

1. 上传手柄测试程序；
2. 打开串口监视器；
3. 分别按下每个按钮；
4. 观察串口是否输出对应按钮名称。

通过标准：

| 操作 | 预期输出 |
|---|---|
| 按 AUTO | `AUTO button pressed` |
| 按 MANUAL | `MANUAL button pressed` |
| 按 STOP | `STOP button pressed` |
| 按 E-STOP | `ESTOP button pressed` |

---

### 12.2 第二步：测试摇杆原始值

目标：确认摇杆 X/Y 轴读数随方向变化。

测试方法：

1. 打开串口监视器；
2. 松开摇杆，记录中值；
3. 前推摇杆，观察 Y 轴变化；
4. 后拉摇杆，观察 Y 轴变化；
5. 左推摇杆，观察 X 轴变化；
6. 右推摇杆，观察 X 轴变化。

记录表：

| 摇杆操作 | X 原始值 | Y 原始值 | 备注 |
|---|---:|---:|---|
| 松手居中 |  |  |  |
| 前推 |  |  |  |
| 后拉 |  |  |  |
| 左推 |  |  |  |
| 右推 |  |  |  |

通过标准：

- 松手时 X/Y 接近中间值；
- 前后推动主要影响 Y；
- 左右推动主要影响 X；
- 数值变化稳定，没有明显跳变。

---

### 12.3 第三步：测试命令转换

目标：确认手柄输入能被转换为 ESP32 内部命令。

| 手柄操作 | 预期内部命令 |
|---|---|
| 前推 | `CMD_FORWARD` |
| 后拉 | `CMD_BACKWARD` |
| 左推 | `CMD_LEFT` |
| 右推 | `CMD_RIGHT` |
| 按 AUTO | `CMD_AUTO_MODE` |
| 按 MANUAL | `CMD_MANUAL_MODE` |
| 按 STOP | `CMD_STOP` |
| 按 E-STOP | `CMD_EMERGENCY` |

---

### 12.4 第四步：接入状态机

目标：确认真实手柄可以替代串口调试命令控制状态机。

操作：

1. 将程序中的：

```cpp
#define USE_JOYSTICK 0
```

改为：

```cpp
#define USE_JOYSTICK 1
```

2. 上传程序；
3. 按 MANUAL，确认进入 `MANUAL`；
4. 推摇杆，确认输出前进/后退/左转/右转动作；
5. 按 STOP，确认回到 `IDLE`；
6. 按 E-STOP，确认进入 `EMERGENCY`。

## 13. 与状态机的关系

手柄输入不直接控制电机，而是先进入状态机判断。

```text
手柄输入
  ↓
ESP32 读取摇杆/按钮
  ↓
转换为内部命令
  ↓
状态机判断优先级
  ↓
安全检查，例如 ToF 防撞
  ↓
输出电机控制信号
```

这样做的好处是：

1. 手动和自动可以统一管理；
2. 急停可以始终最高优先级；
3. 即使手动前进，前方有障碍时也可以强制停车；
4. 后续更换手柄类型时，不需要重写整个状态机。

## 14. 常见问题

### 问题 1：摇杆松手后仍然有动作

可能原因：

- 摇杆中值不是 2048；
- 死区太小；
- 模拟输入有噪声。

解决：

- 增大死区，例如从 `0.20` 改为 `0.25`；
- 实测摇杆中值，修改 `ADC_CENTER`；
- 对 ADC 读数做平均滤波。

---

### 问题 2：前后方向反了

解决：把程序中 `CMD_FORWARD` 和 `CMD_BACKWARD` 对调。

---

### 问题 3：左右方向反了

解决：把程序中 `CMD_LEFT` 和 `CMD_RIGHT` 对调。

---

### 问题 4：按按钮没有反应

检查：

1. 按钮是否一端接 GPIO，一端接 GND；
2. 程序是否使用 `INPUT_PULLUP`；
3. 引脚号是否和实际接线一致；
4. 是否选错了 GPIO；
5. 杜邦线是否松动。

---

### 问题 5：ESP32 重启或烧录失败

可能原因：使用了启动相关引脚，或按钮影响了启动电平。

解决：

- 避免使用 GPIO0、GPIO45、GPIO46 等特殊引脚；
- 烧录时暂时拔掉相关按键线；
- 更换到普通 GPIO。

## 15. 当前版本限制

本说明对应初版手柄输入方案，尚未包含：

1. 无线手柄通信；
2. 航模接收机 PWM/PPM/SBUS；
3. 蓝牙游戏手柄；
4. ESP-NOW 自制无线手柄；
5. 摇杆比例速度控制；
6. 按键消抖完整实现。

后续可以升级为：

- 摇杆推得越多，速度越快；
- 左右转向支持比例控制；
- 增加 ENABLE 使能按钮；
- 增加遥控器断联保护；
- 增加手柄电量显示。

## 16. 结论

初版手柄接入方案采用：

```text
双轴摇杆 ADC 输入 + 按钮 GPIO 输入 + ESP32 内部命令转换
```

核心原则：

1. 摇杆接 3.3V，避免 5V 损坏 ESP32；
2. 按钮采用 `INPUT_PULLUP`，低电平有效；
3. 真实手柄输入和串口调试命令最终都转换成同一套内部命令；
4. 手柄不直接绕过状态机控制电机；
5. 急停必须最高优先级，最好同时包含软件急停和硬件急停。
